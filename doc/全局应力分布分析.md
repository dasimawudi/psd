### 6.1 top1/top5 热点空间分布补充

为进一步判断中心区域 top1/top5 热点是否“到处漂移”，本次直接基于 `resolved_config.yaml` 中的 test split 和 `per_frequency_mises` 原始 target 做了额外统计。口径与 `topk_within25_diagnostics.py` 一致：

- 范围：`dataset.node_scope = disk_center`
- 单位样本：每个 `case-frequency`
- 排名方式：在该样本的 `disk_center` 节点内按真实 `target_raw` 排序，取 top1 / top5

注意：`node_index` 不保证跨 case 物理对齐，因此这里主要看 case 内稳定性、半径分布和局部 patch 紧致性，不直接把不同 case 的同名 `node_index` 解释为同一个物理点。

先看 `disk_center` scope 的组成。100 个 test case 中：

| 项 | 最小值 | 中位数 | 最大值 |
| --- | ---: | ---: | ---: |
| `center_node_mask` 点数 | 1 | 1.0 | 1 |
| `center_couple_mask` 点数 | 3658 | 3764.5 | 3934 |
| `disk_center` 总点数 | 3659 | 3765.5 | 3935 |

这说明当前“中心区域”任务从数据定义上几乎就是“中心耦合区 + 1 个中心点”，不是单独预测几何中心点。

case 内热点稳定性统计如下：

| 指标 | 数值 |
| --- | ---: |
| test cases | 100 |
| `case-frequency` samples | 10607 |
| top1 唯一节点数 / case 中位数 | 1 |
| top1 唯一节点数 / case p90 | 1 |
| top1 唯一节点数 / case 最大值 | 11 |
| top5 union 节点数 / case 中位数 | 5 |
| top5 union 节点数 / case p90 | 6 |
| top5 union 节点数 / case 最大值 | 43 |
| top1 在所有频点固定为同一个点的 case 数 | 96 |
| top5 在所有频点固定为同一组 5 点的 case 数 | 81 |

关键结论：

- top1/top5 并不是在 `disk_center` 范围内大面积漂移。
- 绝大多数 case 里，热点位置非常稳定；变化主要发生在同一个小 patch 上的峰值幅值，而不是峰值空间位置。
- `top5 union` 的中位数就是 5，说明很多 case 里 top5 候选集几乎不换点。

从空间模式上看，中心区域热点更像是两类 case 的混合，而不是单一机制：

| 模式 | case 数 | 现象 |
| --- | ---: | --- |
| 中心点型 | 96 | top1 在所有频点始终落在中心点，且位于 `r < 3 mm` 内核区 |
| 外环型 | 4 | top1 在所有频点始终不落在中心点，而是位于 `r >= 12 mm` 的外环 patch |

当前 test split 中观察到的外环型 case 为：

- `case141_mises_full_export`
- `case70_mises_full_export`
- `case513_mises_full_export`
- `case686_mises_full_export`

top5 的局部紧致性也很强：

| 指标 | p50 | p90 |
| --- | ---: | ---: |
| top5 到 top1 的最大欧氏距离 | 1.72 mm | 2.23 mm |
| top5 到 top1 的其余 4 点平均距离 | 1.52 mm | 1.77 mm |
| top5 半径跨度 | 1.33 mm | 1.65 mm |

这说明 top5 本质上是在刻画一个局部峰值团，而不是多个相距较远的竞争热点。

角度分布上只观察到较弱的 `120°` 周期性倾向，不足以成为主导结论。对多数中心点型 case 而言，真正稳定的是“是否回到中心点/中心小 patch”，不是某个明确的环向扇区。

### 6.2 对上一版判断的修正

基于以上空间分布统计，可以对前一版根因判断做更精确的修正：

1. “真正差的是 top1/top5 和 p99.5+ 极端尾部”这个判断成立。
   现有分位和曲线诊断都支持这一点。

2. “热点问题主要是峰值幅值校准，而不是峰值频率完全错位”这个判断成立。
   曲线诊断已经显示热点峰值频率偏差中位数为 0 Hz，但峰值幅值 pred/target 中位数只有 0.40。

3. “圆盘中心热点不稳定绑定某个清晰几何边界”这句话需要收紧。
   从 test 统计看，热点并不是在 `disk_center` 范围内到处漂移；大多数 case 的 top1/top5 在空间上非常稳定。更准确的说法是：不同 case 之间存在两类热点模式，主流是中心点型，少数是外环型。

4. “当前模型可能缺少局部极坐标、到耦合区距离、模态/FRF 特征”这句话只成立一半。
   当前 `node_mlp_v6_disk_center_baseline` 实际已经包含这几类大特征：
   - 总特征数 238；
   - 几何归一化特征 29 个，包含 `center_region_*`、`center_couple_signed`、`sin_theta/cos_theta`；
   - 距离特征包含 `dist_to_center_couple_region_over_plate_radius` 等 stress region distance；
   - 模态特征包含 modal ratio、modal FRF、modal FRF shape、modal gradient、modal baseline。

因此，当前更可能的问题不是“这些物理特征完全缺失”，而是：

- 现有特征对“中心点型 vs 外环型”两类 case 的区分度仍不够；
- 极端峰值样本权重仍不足，导致模型更倾向于把峰值幅值压回平均水平；
- 少数外环型 case 与多数中心点型 case 混训后，没有形成有效的 case-level 路由或 specialist 行为。

## 7. 对根因的判断

基于现有统计，当前圆盘中心模型的问题可以拆成四类：

### 7.1 低应力噪声区干扰评估

p0-p10 内 target 非常小，相对误差天然敏感。该区间 pred/target 明显大于 1，说明低值点存在过预测。

这类点不应主导模型结论，也不适合作为高应力区效果差的解释。后续评估应单独报告低应力噪声区，避免把低值相对误差和高值峰值误差混在一起。

### 7.2 中高应力区并非不可学

p97-p99、p99-p99.5 的 within25 已达到 0.52-0.54，说明高应力区存在清晰规律，模型能学到一部分。

这支持欧生提出的方向：抽取特定应力区间做快速训练，可以验证在去掉低值噪声和极端尾部之后，模型是否能达到更高的 within25。

### 7.3 热点位置大多稳定，但 case 间存在两类模式

top1/top5 空间分布统计显示，中心区域热点并不是每个频点都在 `disk_center` 内大范围漂移。96/100 个 test case 的 top1 在所有频点始终落在同一个中心点；81/100 个 case 的 top5 甚至始终是同一组 5 个点。

这说明多数 case 的问题不在“找不到热点位置”，而在“找到了同一个热点 patch，但峰值幅值没抬起来”。

但少数 case 又明显不是这一类。`case141`、`case70`、`case513`、`case686` 的 top1 始终落在外环 patch，而不是中心点。这说明当前中心任务至少混合了两种机制：

- 中心点型：主流模式，top1 固定在中心点；
- 外环型：少数模式，top1 固定在外环局部 patch。

这种混合分布会让单一回归头更倾向于学习主流中心点型，而对少数外环型形成系统性欠拟合。

### 7.4 极端峰值仍系统性低估

p99.9 以上 pred/target 下降到 0.82，热点曲线峰值 pred/target 中位数只有 0.40。说明最尖峰值仍被压低。

这可能来自：

- 极端峰值样本占比极小，训练中梯度贡献不足。
- log 回归天然压缩大值幅值差异。
- 当前虽然已经有 center / distance / modal / FRF / gradient 特征，但它们对极端峰值放大倍数和两类 case 模式的区分度仍不足。

### 8.3 快速抽样训练验证

建议优先抽以下区间：

| 实验 | target 区间 | 目的 |
| --- | --- | --- |
| A | p10-p75 | 验证去掉低值噪声和高值尾部后的基础可学性 |
| B | 1e4-1e5，约 p90-p97 中段 | 对齐欧生要求的 10^4-10^5 区间 |
| C | p95-p99 | 验证高应力区是否能通过区间抽样提升 |
| D | p99-p99.5 | 验证高值尾部但非最极端点 |
| E | p99.5+ | 单独验证最极端峰值是否需要特殊处理 |
| F | 中心点型 case vs 外环型 case | 验证是否需要 case-level 路由、MoE 或 specialist |

每个实验记录：

- 样本量。
- target 区间。
- train/val/test 分布。
- log MAE。
- within25。
- top1/top5 within25。
- pred/target。
- under/over pred ratio。

### 8.4 判断标准

如果 B/C/D 区间单独训练后 within25 明显上升到 0.60-0.70，说明当前主要瓶颈是数据分布混杂和样本区间不均衡。

如果 B/C/D 单独训练仍无法提升，说明问题更可能来自特征表达或目标噪声，需要回到特征分桶、数据平滑或异常数据排查。

如果 E 区间仍明显低估，但 B/C/D 正常，则极端峰值应作为单独兜底问题处理，不能用它否定整个圆盘中心模型。

如果 F 显示中心点型和外环型 case 的最优策略明显不同，则后续不应再把它们视为同一种中心热点问题；应优先考虑 case-level routing、hotspot type classification 或两类 specialist。
